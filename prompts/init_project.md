현재 업로드된 프로젝트(소스코드/파일/구조)를 전체 분석해서,
장기 유지보수와 AI 협업을 위한 Markdown 문서를 생성해줘.

목표:

* 다른 AI나 새로운 대화창에서도 프로젝트를 이어서 작업 가능해야 함
* 사람도 문서를 읽고 현재 프로젝트 상태를 이해할 수 있어야 함
* 긴 대화 기록에 의존하지 않고 문서만으로 프로젝트 컨텍스트를 유지해야 함
* 특정 AI 전용 형식이 아닌 범용적인 문서 구조를 유지해야 함
* 과도한 문서 분리는 하지 말고 핵심 정보만 요약해서 관리해야 함

다음 4개의 Markdown 문서를 생성해줘.

1. PROJECT.md
   역할:

* 프로젝트의 전체 개요와 구조 설명
* 기술 스택
* 핵심 기능
* 디렉토리 구조
* 주요 설계 방식
* 핵심 규칙 및 제약사항
* 프로젝트 목적과 동작 흐름

중요:

* 새로운 AI가 처음 읽어도 프로젝트 구조를 이해할 수 있어야 함
* 너무 장황하지 말고 핵심 위주로 정리
* 추정 내용은 "추정"이라고 명시

2. STATUS.md
   역할:

* 현재까지 진행된 개발 상태 기록
* 완료된 기능
* 현재 작업 중인 기능
* 다음 작업 예정 항목
* 현재 발견된 문제점 또는 기술 부채

중요:

* 현재 시점 기준으로 작성
* 실제 개발 진행 상황 중심
* 불필요한 과거 기록은 최소화

3. HANDOFF.md
   역할:

* 다음 AI/다음 세션이 바로 이어서 작업 가능한 인수인계 문서
* 현재 가장 중요한 작업 상태 요약
* 수정 시 주의사항
* 절대 변경하면 안 되는 부분
* 다음 우선 작업 순서
* 현재 막혀있는 문제

중요:

* 짧고 압축적으로 작성
* 실무 인수인계 문서처럼 작성
* "지금 바로 이어서 작업할 사람" 기준으로 작성

4. README.md
   역할:

* 프로젝트 기본 소개
* 실행 방법
* 설치 방법
* 필요한 환경
* 빠른 시작 가이드

중요:

* GitHub 기준으로 일반 개발자가 읽을 수 있게 작성
* 프로젝트 실행에 필요한 최소 정보 포함

공통 작성 규칙:

* Markdown 표준 문법 사용
* 사람이 읽기 쉬운 구조 유지
* 불필요하게 긴 설명 금지
* 핵심 내용을 우선 정리
* 실제 코드 기반으로 분석
* 모르는 내용은 추측하지 말고 명확히 구분
* AI 전용 문체가 아닌 일반 기술 문서 스타일 유지

마지막에는:

* 현재 프로젝트 구조의 문제점
* 유지보수 위험 요소
* AI 협업 시 개선하면 좋은 부분

도 간단히 정리해줘.
